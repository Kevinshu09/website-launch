# 表单与 Google Sheets

作者：Kevin Shu · GitHub：kevinshu09

## 选择保存位置

优先复用合适的现有服务。Google 表格适合简单线索列表，不等于事务数据库、登录系统或敏感记录平台。字段和必填项取自本项目需求，不照搬其他客户信息。

两步问卷通常第一步验证并在页面内存中保存，第二步发送完整记录。第一步写“继续”，不写“已收到”。失败时保留输入，防止连续点击，确认成功后再清空。必要时提供返回修改；不为方便而默认将线索存进浏览器持久存储。

## 可选架构

网站 → 同源服务器接口 → Google Apps Script Web 应用 → 私人 Google 表格。

服务器负责调用 Google，避免浏览器跨域造成无法读取确认结果，并将连接密钥留在服务器配置中。正常跟随 Apps Script 内容响应的重定向；不能把无响应确认或 opaque 响应当成保存成功。

先确认托管平台支持服务器功能。有现成服务器凭据时也可以采用 Sheets API。Drive 连接器能编辑表格，不代表能创建或部署 Apps Script；先检查实际工具能力。

## 保存可靠性

- 服务器验证字段类型、长度、必填项和邮箱；下拉值与当前问卷一致。
- 为每条询盘生成请求 ID，失败重试保持同一 ID。
- 接收端验证每个项目独立生成的连接密钥，不在前端或 URL 暴露。
- 在锁或等效原子机制内按 ID 查重，再追加记录；数据量增大时限制搜索范围或更换存储方案。
- 将公式样式的用户输入按文本保存，防止作为表格公式执行。
- 写入确认或已存在相同 ID 后，返回包含该 ID 的成功结果。
- 超时、权限拒绝、无效内容与上游失败时不显示假成功，不输出个人信息或密钥到日志。

隐藏诱捕字段、请求大小限制属于基础防护。Origin 检查不是身份认证或完整机器人防护；遇到滥用或较大流量，应采用适当的服务器验证挑战和限流。核实额度与保留期限，不声称无限量。

## 账号与密钥

准备脚本与操作说明放在网站公开目录之外。每次安装生成新密钥，不复用别人的部署地址、表格 ID、收件人或账号。通过安全配置保存密钥，导出时排除 .env、认证文件及含密钥脚本。

初始化函数可创建私人表格、表头并记录 ID，重复执行复用已有表格。指定现有表格时，先检查结构并保留记录和权限。Google 权限限于所需范围。邮件通知与自动回复是独立功能，没有授权和配置时不添加、不宣称已启用。

## 需要用户完成的 Google 操作

先检查是否有合适工具可执行；可用时通过已授权工具操作。不能绕过浏览器或账号的访问限制。

需要用户操作时，先提供完整脚本，再逐步指导；具体界面有变化时查当前官方文档：
1. 在应拥有询盘的 Google 账号中创建 Apps Script 项目。
2. 粘贴代码、保存、选择初始化函数并运行。
3. 用户审阅并授权所需权限，保持表格私有。
4. 部署为以拥有者身份执行的 Web 应用。公开网站通常要求访问范围为 Anyone；公开的是检查连接密钥的接收入口，不是表格读取权限。
5. 获取真实的 `/exec` Web 应用地址，不接受编辑器网址、单独部署 ID 或带省略号的示例。

若组织禁止匿名入口，改选被允许的后端，不修改组织安全政策。授权错误应检查实际详情；短暂重试可以合理，但不能通过绕过警告解决 invalid_client，也不能反复盲建项目。

修改源代码后可能需要更新部署版本，保存代码不代表线上版本已改变。

## 实际验证

配置并部署后，用明显标注 TEST 的非敏感样例通过网站接口提交。读取目的地确认全部字段；HTTP 200 可能只是登录页面，不代表成功。

以同一 ID 重试一次检查重复保护；失败后先诊断，避免反复制造记录。偶发失败后一次成功不证明错误不会再出现，需说明尚未解决的可靠性问题。

默认保留一条有标记的测试记录，已获授权清理时再删除；不能改动真实询盘。分别说明表单、存储、通知和浏览器完整操作是否验证。
