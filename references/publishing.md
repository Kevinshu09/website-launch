# 上线与自定义域名

作者：Kevin Shu · GitHub：kevinshu09

## 目标与范围

遵守用户选择的托管平台和既有项目。检查实际工具及登录状态，不把技能存在当成连接器已经登录。配置与命令可能变化时查官方文档。

先确定项目、代码目录、生产目标。不因共用账号而修改其他网站。仅部署网站及必要服务端代码，排除私人需求文档、凭据、含密钥安装脚本和交接记录。

使用官方登录和刷新机制，不打印认证文件或在命令参数暴露密钥，不索取聊天密码。缺少登录时说明具体授权步骤，不虚构部署成功。

## 发布

运行适当检查后部署并读取结果。用户已授权本网站发布时继续完成，不重复询问；未知的重要目标或超出范围的操作另行确认，不擅自购买服务或迁移域名。

READY 只证明构建完成，不证明匿名访客可访问。检查目标网站访问保护，仅在用户授权范围调整，不影响其他项目。

使用 Vercel 等平台的服务器表单接口时，确认接口确实执行，不是返回源码或 404。环境变量配置后重新部署并验证当前版本。

## 域名

从用户说明确认准确域名。区分注册商与实际 DNS 管理方，修改前检查已有记录和用途。

将主域名绑定正确生产项目，需要时添加单向 www 重定向。使用平台当前针对该项目给出的 DNS 值，不复制旧项目 IP 或 CNAME。

只修改必要网站记录，保留邮件、验证和其他子域名。更换 nameserver 影响整个 DNS 区域，不能作为默认捷径；需要明确授权并确认现有记录已纳入迁移。

无法直接操作 DNS 时提供准确的类型、主机名、值。用户完成后再验证，不把给出操作说明当作已经连接。

## 分项验证

1. 部署已完成，访问范围符合要求。
2. 主域名返回正确网站内容，HTTPS 证书有效。
3. 次域名正确重定向，没有循环。
4. 图片、字体与脚本能加载。
5. 已配置表单确实保存一条测试记录。

DNS 显示正确不等于 HTTPS 已正常。遇到传播或证书问题，应报告已确认与失败的部分，不承诺固定生效时间，也不关闭证书校验。未获请求不安排持续监控。

## 交接

提供验证后的链接、询盘位置、剩余账号操作与未配置功能。部署 ID、代码位置、配置变量名称和检查记录放在私人交接文件里。

分享技能或代码前扫描个人信息与密钥。通用流程不得自动连接原作者账号、使用原作者表格或复制旧提交历史。
